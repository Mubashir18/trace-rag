# Remote-Monitoring Tool Abuse: Unauthorised "Ashvale" Agent Installed via Help-Desk Pretexting

## ACTIONS TO TAKE TODAY
1. Search proxy and DNS logs for the network indicators in Table 1.
2. Search EDR alerts for the agent hash in Table 2 and uninstall the agent where it is not approved.
3. Tell staff that the help desk never asks them to install remote-support software by phone.

## SUMMARY
An actor tracked here as COBALT TERN (fictional) phones staff at insurance companies, claims to be
from the internal help desk, and talks them into installing a remote-management product called
Ashvale (a fictional product). Ashvale is a real-looking support tool, so it is rarely flagged as
malware, but it gives the actor full remote control. The actor then signs in remotely with the
victim's password. Every host that reached the join page or the relay should be reviewed.

## TECHNICAL DETAILS
### Initial Access
During the call the victim is asked to open remote-assist-portal[.]example[.]net and enter a
"session code" [T1566.004]. The page downloads `AshvaleAgent.exe`.
### Persistence and Remote Access
The agent installs itself as a service [T1543.003] and keeps a connection open to the relay
ashvale-connect[.]example[.]com [T1219]. On some hosts the relay was blocked after the DNS lookup.
### Lateral Movement
The relay resolves to 203.0.113.163, the same address the actor later used to sign in remotely
with the victim's account [T1078].
